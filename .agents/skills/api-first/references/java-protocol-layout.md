# Java协议对象分包与命名

<a id="protocol-package-layout"></a>
## 必须按职责分包

api-first 负责 Java 协议类型的目录和命名。CODER 编写或审查相关声明时直接使用本规则。先读取目标项目已有且仍有效的协议目录、类型和调用方，沿用已确认的业务根包及命名风格，不硬编码某个公司或业务的全限定包名。

| 对象职责 | 所属包 | 类名 |
| --- | --- | --- |
| HTTP写入参数 | `<业务根包>.protocol.param` | `XxxParam` |
| HTTP读取条件 | `<业务根包>.protocol.query` | `XxxQuery` |
| 对外返回结果 | `<业务根包>.protocol.dto` | `XxxDTO` |
| 类型、状态或业务错误枚举 | `<业务根包>.protocol.enums` | 按已确认的业务含义命名 |

- **协议根包不能作为Param、Query、DTO和枚举的统一堆放目录。** 先确定对象的真实职责，再确定子包；不能只改文件名而保留错误的package或文件路径。已有消息`event`等子包按项目真实消息职责继续使用，不将Event当HTTP参数或返回DTO，也不为了目录完整创建空包、无用类或额外分层。
- HTTP Query 表达调用方可传的筛选条件。数据库查询类型和映射规则见 [CODER 的数据库分页查询对象](../../coder/references/java-persistence.md#query-converter)。
- **纯数据返回直接复用已确认的DTO。** 不为了逐层传递重复生成同字段BO或仅做BO到DTO复制的组装层；保留确有领域职责、行为或不同数据含义的对象，不据此批量删除所有领域对象。分页、错误和统一响应沿用项目既有公共类型。
- 设计阶段核对新声明的类名、包、目标路径、依赖方向和实际调用方，按[接口源码交付规则](../SKILL.md#design-source-delivery)交付兼容声明或拟议差异。沿用用户已确认的包名和字段。
- 移动仍被引用的类型时，列出受影响的 import、调用方、测试、配置和 TRD 引用。获准迁移后同批更新，再检查应迁移位置的旧包引用、受影响模块的编译及必要的协议用例。已明确保留的兼容入口按批准的范围单列，历史日志保留其原始内容。移动文件时保留原业务含义和序列化约定，发现需要兼容副本或行为变化时先报告。
