# Java 类型引用规范

<a id="java-type-imports"></a>
## 所有阶段统一使用 import 加类名

适用于 Java 技术设计、TRD 接口定义、协议声明、文档代码示例、源码生成、正式代码、测试、重构及审查。`trd-writer`、`coder`、主工作流和审查流程遵守同一规则，不能等到编码阶段才处理。

- **所有类、接口、注解和异常类型通过文件顶部的 `import` 引用，代码正文只写类名，禁止直接使用全限定类名。** 字段、方法参数与返回值、`throws`、泛型、继承与实现、注解、对象创建、类型转换及静态方法调用均适用。
- TRD 中的接口声明和 Java 代码示例同样写出必要的 `import`，不以“只是文档”“不是完整源码”为理由在签名中使用全限定类名。只展示某个方法片段时，可在同一示例前列出所需导入；已引用实际源码时不必重复抄写源码。
- `package`、`import` 声明中的包路径，以及反射所需的类名字符串和配置中的类名，不属于正文类型引用。`java.lang` 和同包类型等无需导入的类型直接写类名，不添加无用导入，不改动运行时需要的类名字符串。
- 同名类型冲突优先使用已有接口、必要的静态 `import` 或按实际职责区分名称；互相独立的同名测试场景可拆分到独立测试类。不增加无业务意义的包装层；仍无法消除时明确报告冲突，不擅自使用全限定类名绕过规范。
- 交付前检查本次范围内的全部 Java 类型引用，包括 TRD、接口定义、代码示例、正式源码和测试，补齐导入并清理重复或无用导入。用户明确要求全面修改时，检查当前仓库全部 Java 源码和测试，排除构建产物、依赖、注释及上述非类型引用。源码变更执行必要编译；仅规则或文档变更检查内容一致性和引用链接。未检查或未编译的范围如实说明，不声称已经统一或验证通过。

正确示例（方法片段）：

```java
import com.lingcheuk.protocol.BusinessException;

ProjectDTO detail(Long id) throws BusinessException;
```

其中 `ProjectDTO` 按目标项目实际包位置导入；同包时无需导入。禁止将方法写成 `ProjectDTO detail(Long id) throws com.lingcheuk.protocol.BusinessException;`。
