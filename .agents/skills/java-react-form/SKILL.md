# Java 类生成 React 表单

生成单个实体的新增／编辑 React 组件及对应 TypeScript **类**。不扩展为列表、查询、删除、路由或后台接口。保存通过 `onSubmit` 交给调用页面，表单负责输入、校验和编辑回填。

## 先取得输入，再确认字段

1. 调用时先问用户：“这次根据哪个 Java 类生成？请给类名或文件路径。”若用户本轮已明确指定，直接读取，不重复询问。不得自行挑选示例类作为生成目标，也不要求用户先手写 TypeScript。
2. 在目标业务项目读取适用的 `AGENTS.md`，定位 Java 类、父类、字段注解、引用枚举和相关序列化约定。类名有多个匹配时给出候选让用户选；已有代码能够查清的事实自行核实。不得修改用户提供的 Java 类来迁就前端。
3. 查找目标模块的 `common/components/forms/validatable-*`、`validable-two-switch.tsx` 及实际调用，核对导出名、参数、数据类型、表单库、校验和翻译方式、输出目录。通过软链接加载本 skill 时，包内参考文件按真实路径读取；业务源码从当前目标项目读取。阅读[组件核对说明](references/component-contracts.md)，其中的历史观察必须用当前源码复核。
4. 展示字段清单：`Java 字段／类型 | TypeScript 类型 | 组件 | 单选／多选 | 新增／编辑初值 | 校验规则 | 数据来源`。列明隐藏、只读、不生成输入框的字段及原因。仅向用户询问注解、协议和现有约定仍不能确定的项目；给出建议及实际区别。
5. 用户确认字段清单、必要的未决行为和本次生成范围后再写入。已有同一范围的明确确认不重复索取。遵守目标项目的方案与实施授权要求；本 skill 不代替复杂改造所需的技术方案确认。公共组件能力缺失按下述规则处理。

## 字段到组件的规则

先识别 Java 类型和 `InputDatasource`。`boolean`／`Boolean` 使用普通布尔开关；其他类型再按数据源匹配。数据源和单多选是两件事，分别判断：

| 字段含义或注解 | 使用的组件 |
| --- | --- |
| Java `boolean`／`Boolean` | `validatable-switch.tsx` 的 `ValidatableSwitch` |
| 非布尔标量，`InputDatasource.type = TWO_SWITCH` | `validable-two-switch.tsx` 的 `ValidatableTwoSwitch` |
| `InputDatasource.type = UPLOAD`，或已明确是图片上传 | `validatable-image` |
| 选择数据源且 `tree = true` | `validatable-tree` |
| 其他选择数据源，含 `DICTIONARY`、`TABLE`、`ENUM` | `validatable-select` |
| 日期输入 | `validatable-date` |
| 普通文本输入 | `validatable-input` |
| 已明确的长文本输入 | `validatable-textarea` |

- `boolean`／`Boolean` 与 `TWO_SWITCH` 等数据源注解冲突时，以普通布尔开关为准，并在字段清单中明确列出冲突注解；不修改 Java 注解，也不把布尔值编码成 `0/1` 或 `"true"/"false"`。
- `TWO_SWITCH` 是两个业务选项之间的单选，必须提供**恰好两个**不同的 `string | number` key，保留协议规定的 key 类型。动态选项先核对数量、类型和重复值，再构造 `TwoSwitchOptions<T>`；不得截取前两项、强制断言元组或伪造选项。缺失、加载失败或不是两项时显示明确状态并阻止该字段提交；数组／集合或 `tree=true` 与双选不兼容，列出冲突，不擅自改成其他控件。绑定及空值细节见[双选与布尔开关](references/component-contracts.md#双选与布尔开关)。
- 对非布尔字段，`UPLOAD` 优先于字典和树判断；`params` 的上传分类或字典参数含义按当前实现读取，不拼造接口。`NULL` 或未知数据源类型没有明确选项来源时，先指出缺失并询问，不能伪造字典。
- 对选择字段，普通标量为单选，数组／集合为多选；`tree=true` 时仍遵守此规则。不能把树的父子联动选项当成单选／多选开关。父子联动、可选节点范围若影响提交值且无现成依据，列为待确认行为。
- 没有数据源的数组／集合不自动成为字典，也不直接塞进普通文本框；明确其编辑方式后生成。嵌套对象同样不能擅自展开成一套子表管理。
- 类、注解或现有协议不能区分普通字符串、长文本、图片时，向用户确认；不能仅凭字段名把猜测写成既定规则。必填、长度、范围、标题、日期格式、只读和字段顺序同理。
- 正确文件名是 `validatable-textarea`；用户口述的 `textare` 指长文本输入，不据此创建新组件。

## 公共组件能力不足

读取当前实现后，如果所需单选／多选、值类型、日期行为或图片数量不受支持，展示具体差距及影响，先请用户确认是否扩展公共组件。扩展属于额外修改范围，应遵守目标项目的方案、授权和验证要求；确认后才能继续生成依赖它的部分。

不得传入不存在的 `multiple`、`single` 等参数，不能用强制类型转换掩盖不兼容，也不能用多选数组截断等方式假装实现了单选。未获扩展授权时，只处理已获授权且独立可用的部分，并明确未生成项；不把缺功能的结果描述成完整交付。

## TypeScript 类与提交数据

- 生成对应的 TypeScript `class`，不能只交付 `interface` 或 `type`。若已有对应类，先核对并复用／在确认范围内更新，不创建重复模型。
- 字段名、序列化名、可空性、数组元素类型、枚举值与实际 Java／JSON 协议一致；继承字段按真实序列化和编辑范围处理，跳过静态常量等非数据字段。
- 数值类型要结合真实传输格式：Java `Long`、大整数和 `BigDecimal` 不一律转换为 JavaScript `number`。协议不明时明确精度问题并询问，不能静默改变 ID 或金额。
- 日期格式、时区以及日期与时间的区别按实际协议处理，不把所有日期统一成时间戳或 `Date` 对象。
- 表单控件中的字符串、树节点 ID 与提交字段可能不同，明确回填和提交两方向的转换。字典 key、节点 id、业务 code 不可混用；数组不能转换成逗号拼接字符串，除非实际协议明确如此。
- 按协议区分 `undefined`、`null`、空字符串、空数组和未选择值。不能把 `InputDatasource.defaultValue` 的默认 `"-1"` 直接用于所有类型；双选仅在明确默认值且与真实选项 key 的值和类型一致时采用，否则保持未选。不能用 `String(undefined)`、`Number("")`、`Boolean("false")` 等制造错误初值。
- `Boolean` 的 `null`／`undefined` 不自动变成 `false`；普通开关只接受 boolean，显示时的关闭状态不能回写为模型默认值。非空必填只排除缺失，`false` 是有效值；只有明确要求必须开启（如同意条款）才使用 `requiredChecked`。需要用户明确选择第三种未设置状态且当前开关无法表达时，按公共组件能力不足处理。
- Java 类定义不能单独确定字段编辑权限。系统标识、租户、审计等字段按实际接口和权限约定隐藏、只读或排除，不默认变成可编辑输入。

## React 组件的职责

- 复用项目既有的表单库、校验工具、布局和翻译方式，不引入另一套组件体系。需要的校验文件及翻译资源按目标项目约定组织，随组件一并说明。
- 新增／编辑可复用主体或按项目习惯分别导出，但必须都能使用。提供明确类型的初始数据、选择数据和 `onSubmit` 输入；名称和文件位置遵循目标项目约定。
- 字典／树选项复用已存在的数据供应方式，或由调用页面通过有类型的 props 提供。类注解本身不等于可访问的接口，不根据类名或 `params` 猜 URL，也不为了获取字典生成列表页。
- 组件校验成功后将与 TypeScript 类一致的数据交给 `onSubmit`；异步回调应被等待，提交期间避免重复提交。保存失败保留输入并按项目约定反馈，不能吞掉失败或提前显示成功。
- 组件不直接调用业务保存接口；保存、页面刷新和关闭由调用方处理。图片组件自身已有的上传功能可复用，它不属于业务表单保存接口。
- 编辑必须正确回填标量、数组、字典、树、图片和日期；核查异步加载及切换记录时的更新行为。不能仅传一次 `defaultValue` 就假定所有组件都会刷新，也不能让字典到达后覆盖用户已输入内容。

## 验证与交付

按实际生成范围运行目标项目已有的类型检查及必要验证。至少核对新增默认值、编辑回填、有效提交的字段和值类型、无效输入拦截；涉及选择时核对单多选和空值；涉及双选时核对恰好两项、动态错误选项、key 类型和编辑旧值失效，涉及布尔开关时区分 `false`、缺失与必须开启；涉及异步回填或提交时核对切换记录、加载和失败行为。沿用现有测试设施，不为生成组件搭建无关业务环境。

交付说明 Java 来源、生成文件、字段映射、父组件调用方式、实际执行的验证及仍未完成的部分。示例使用真实存在的导出和参数，未执行的运行验证如实标注。生成技能或通过类型检查不能代替业务页面验收。
