## 3. F02：依赖安装目录检查方案

**不需要用户准备环境、提供账号或补充配置。这是脚本自身的检查缺口，由维护者修复。**

现状：指定依赖目录时，`setup.mjs` 只阻止写入 `scripts/`，未保护整个共享技能源；目标末级目录不存在时，也没有识别父目录软链接。例如表面指向临时位置的路径，实际可能写回共享 skill 源目录。默认用户级依赖目录不受这两个复现场景影响。

修改范围为 [setup.mjs](../skills/develop-work-flow/scripts/setup.mjs) 与 [workflow.test.mjs](../skills/develop-work-flow/scripts/workflow.test.mjs)：

1. 根据脚本实际位置确定共享技能包 `.agents/` 的真实路径，作为禁止安装第三方依赖的范围，不只比较 `scripts/`。
2. 对尚不存在的目标，找到最近存在的父目录，取得其真实路径，再拼接尚不存在的目录部分；指向不存在目标的软链接应拒绝，不当成普通缺失目录。
3. 比较目标真实位置与共享源范围。目标在共享源内部时，在创建目录、复制清单、调用 npm 之前返回明确错误。
4. 保留当前用户级默认目录、专用目录检查和既有文件保护；不修改用户全局配置，不需要真实网络安装来证明拒绝行为。

验证使用临时副本与假 npm：共享源内的同级子目录、经父软链接进入共享源的不存在目录，都必须失败，且无新增清单、无 npm 调用；独立临时依赖目录应通过。复用已有测试核对软链接、清单保护和正常调用路径。

**状态：moderate，仍扣 4 分，尚未实施。** 原复现、影响及依据见 v1 的 F02。下一实施环节由 AI 修改上述两个文件并执行相关测试，不需要新的业务取舍。

## 4. F03：Git 内部目录检查方案

**对每一段路径统一按小写比较，拒绝 `.git` 的所有大小写写法。** 例如 `.git`、`.GIT`、`.Git` 都拒绝；`.github` 和普通业务文件正常允许。

修改范围为 [workflow.mjs](../skills/develop-work-flow/scripts/workflow.mjs) 的 `safePath`、`projectFile`，以及 [workflow.test.mjs](../skills/develop-work-flow/scripts/workflow.test.mjs)：

1. 将两处只识别精确字符串 `.git` 的判断统一为 `part.toLowerCase() === '.git'`，必要时提取一个局部辅助函数供两处使用。
2. 保持现有项目范围、点路径和软链接检查；无需改变 DSL、任务状态或输出格式。
3. 对任务 `files` 和设计 `design` 引用补充三种大小写测试；在临时项目中运行，确认全部返回 `UNSAFE_PATH`，不读取或改动真实 Git 内部文件。
4. 补充正常路径对照，并执行现有脚本测试，确认不会误拒绝 `.github` 等普通目录。

这种做法在大小写敏感和不敏感的文件系统上采用一致规则，不需要新增依赖，也无需用户调整文件系统设置。

**状态：moderate，仍扣 4 分，尚未实施。** 原复现、影响及依据见 v1 的 F03。下一实施环节按上述范围修改和验证。
