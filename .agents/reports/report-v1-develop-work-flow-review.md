**流程方向可行，本轮结论为“待修订”，评分 84/100。** 当前规则能够组织“AI 完成各阶段工作、用户确认关键交接、脚本校验和生成计划”的研发过程。阶段职责、API FIRST、同一版本审查、授权复用、返工和证据失效处理基本自洽，但仍有 4 项已确认问题，详见第 4 节；不能宣称当前规则完全一致或本轮审查通过。

## 4. 全部已确认问题

### F01：lite 模板仍允许合并或省略章节

- **严重性与扣分：major，6 分；阻止本轮给出通过结论。**
- **位置：** [lite/technical.md](../skills/develop-work-flow/assets/lite/technical.md) 第 5 行；冲突依据为主工作流 [模板结构与内容检查](../skills/develop-work-flow/SKILL.md#template-structure)，当前第 245—251 行。
- **事实：** lite 入口仍写“合并或省略无关章节”；最新主规则要求保留标题、编号、顺序与层级，只省略不适用的内容。
- **触发：** 编写者按 lite 入口合并章节，审查者按主规则检查章节完整性。
- **影响：** 同一份方案按一个入口写完后又被另一个入口打回，直接重现用户要求解决的重复返工问题。这是此前同步遗漏，不能归因于用户再次改变要求。
- **最小修正：** 删除 lite 入口的旧许可，引用主工作流 `#template-structure`；不在该入口重新复制一套模板规则。
- **复查：** 沿 lite 分流、trd-writer、lite 模板和共用 TRD 模板逐项核对，确认不存在“可删标题”与“必须保留标题”并存；对省略内容的样例检查标题仍完整。
- **处理方：** 工作流维护者；已有明确用户结论，不需要重新讨论业务取舍。

### F02：setup 对共享源目录的保护范围不完整

- **严重性与扣分：moderate，4 分；非主流程阻塞项。**
- **位置：** [setup.mjs](../skills/develop-work-flow/scripts/setup.mjs) 第 19—24 行；对照 [脚本入口](../skills/develop-work-flow/SKILL.md#script-entry) 第 770—776 行“不安装到共享 skill 源目录”的约定。
- **事实：** `source` 实际只指向 `scripts/`，检查不会拒绝同一 skill 下的其他子目录；当目标末级目录尚不存在时，使用 `path.resolve`，不会解析已经存在的父目录软链接。
- **触发与实测：** 在临时 skill 副本中，将依赖目录指向 `skill/deps`，或指向经父软链接到达的 `skill/scripts/deps`。两例均退出 0，复制清单并调用假 npm。
- **影响：** 配错 `AI_CODING_WORKFLOW_DEPS` 时可以向共享源写入依赖清单，并在真实运行时启动该位置的依赖安装。默认用户级目录不受这两个场景影响；本轮未污染真实共享源，也未执行真实 npm 安装。
- **最小修正：** 明确整个共享 skill 源目录的拒绝范围；对不存在的目标，解析最近存在的父目录真实路径后再拼接后缀。所有检查在复制清单、创建目录及启动 npm 前完成。
- **复查：** 两个复现场景都应在写文件和调用 npm 前失败；正常独立依赖目录应成功。不需要扩大为通用安装平台改造。
- **处理方：** 工作流脚本维护者；不涉及新业务决定。

### F03：大小写不敏感文件系统可绕过 `.git` 路径检查

- **严重性与扣分：moderate，4 分；非主流程阻塞项。**
- **位置：** [workflow.mjs](../skills/develop-work-flow/scripts/workflow.mjs) 第 65、82 行；[现有测试](../skills/develop-work-flow/scripts/workflow.test.mjs) 第 351—356 行只覆盖小写 `.git`。
- **事实：** 路径保护采用区分大小写的字符串比较；本机测试卷中 `.GIT` 与 `.git` 指向同一目录。
- **触发与实测：** 在临时项目放置虚构的 `.git/config.md`。任务 `files` 引用 `.GIT/config.md`，以及设计引用 `../../.GIT/config.md#internal`，均通过 validate；小写对照组被 `UNSAFE_PATH` 拒绝。
- **影响：** Git 内部路径可被当作正常任务文件或设计输入接受。CLI 不执行任务文件，本轮没有证明或造成真实 Git 文件损坏；问题是其声明的路径边界没有守住。
- **最小修正：** 拒绝 `.git` 的大小写变体，或依据实际文件身份判断，保证输入及输出经过同一保护。
- **复查：** 在大小写不敏感文件系统验证 `.git`、`.GIT`、`.Git` 的任务路径和设计引用均被拒绝；其他文件系统明确对应条件，正常项目路径仍可使用。
- **处理方：** 工作流脚本维护者；不涉及新业务决定。

### F04：并行执行同时被描述为必须和按需

- **严重性与扣分：minor，2 分；非阻塞项。**
- **位置：** 主工作流 [并行执行](../skills/develop-work-flow/SKILL.md#collaboration) 第 594 行及 [通知规则](../skills/develop-work-flow/SKILL.md#notify) 第 607 行；对照主流程第 30 行，以及 [coder](../skills/coder/SKILL.md) 第 68 行。
- **事实：** 两处要求无依赖且文件不冲突的任务“用 sub-agent 并行启动”；其他入口允许自行编码，适合时再分工。
- **触发：** 两个很小的独立任务，或宿主不具备子代理能力。
- **影响：** 执行者可能被迫为很小的任务调度代理，或者因工具缺失无法按字面执行；不同入口得到不同安排。该问题不等于业务结果错误。
- **最小修正：** 在主工作流统一为按工作量、独立性、实际收益和宿主能力选择；不适合或不可用时由主代理串行完成。通知表和 coder 引用该规则，不另建判断标准。
- **复查：** 小任务串行、足够工作量的独立任务并行、宿主无子代理时回退串行，三种路径都不越过阶段授权，也不并发覆盖共享记录。
- **处理方：** 工作流维护者；遵守用户已经明确的按收益分工原则，无须新增选择题。

## 6. 已接受边界、未验证范围和未决项

以下不作为本轮缺陷或扣分项：

1. 用户要求各独立阶段交付后确认；同一对象和范围的批准可复用。人工确认不能被测试或审查通过替代。
2. CLI 检查结构、引用、状态及证据字段，不判断用户批准真伪，也不证明记录中的测试实际运行；这些由执行者、审查者和用户核实。
3. `check` 允许状态文件尚不存在，但主流程明确要求先执行 `status`、再执行 `check` 并核对文件存在，当前文档与实现对此一致。
4. 来源改变后评审失效有明确规则；不影响语义的记录整理另有处理说明，不能仅因存在 hash 更新就判定一定陷入反复审批。
5. 通知失败有如实记录及继续其他已授权任务的边界，本轮没有实际发送通知。
6. 测试按当前风险设计，不机械要求每个接口凑齐六组测试，也不为流程审查启动业务构建。

尚未验证：真实新需求从 REQ/PRD/TRD 到编码、独立验收和发布的完整运行；通知邮件实际投递与宿主会话钩子；不同操作系统和 Node 版本的组合；真实 npm 安装行为。本轮仅在当前机器对既有测试与必要临时复现作了验证，不据此声称生产发布已经可用。

没有需要用户重新决定的业务问题。F01—F04 的最小修正均可直接依据已有规则实施，但本轮请求是 review，未开始修正。建议下一环节只维护这 4 项及对应回归验证，完成后再交付复审结果；业务开发、提交和发布不属于该维护范围。
