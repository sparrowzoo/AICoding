# greeting — 技术设计

> 模式: 精简版 (小需求)

## 1. Context

实现一个纯函数问候工具。单函数、无外部依赖、无状态、无 I/O。

约束:
- 无第三方库
- 单一职责
- 防御性编程处理边界

## 2. Decisions

| # | 决策点 | 选型 | 替代方案 | 理由 |
|---|--------|------|----------|------|
| 1 | 异常策略 | 参数清洗优先 | 抛异常 | 问候无失败场景，清洗比抛异常更友好 |
| 2 | 超长截断 | `String.substring(0, 100)` | 抛异常 / 原样返回 | 保留最自然的行为 |
| 3 | null 处理 | `Objects.toString(name, "")` 统一转空串 | 单独 `if` 分支 | 减少分支，与空串合并处理 |

## 3. Data Model

本次变更不涉及数据模型。

## 4. API / Contracts

```java
public static String greet(String name)
```

| 参数 | 类型 | 约束 | 说明 |
|------|------|------|------|
| name | String | 可 null | 用户名 |
| 返回值 | String | 非 null | 问候语 |

异常/边界处理逻辑:

```
输入 name
  ├── null → 转为 ""
  ├── 空串 "" → 替换为 "匿名用户"
  ├── 长度 > 100 → 截断前 100 字符
  └── 正常 → 原样使用
最终 → "你好，{name}"
```

## 5. Flows

核心流程 — 单函数无分支嵌套，按优先级串联:

```
1. null 安全转换 (null → "")
2. 空串判断 ("" → "匿名用户")
3. 超长截断 (>100 → substring(0,100))
4. 拼接 "你好，{result}"
```

决策点:
- null 和空串合并处理，减少分支
- 截断在空串替换之后，避免 "匿名用户" 被截断（其长度为 4 < 100，不影响）

## 6. Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 截断可能产生不完整字符 | UI 显示异常 | Java substring 按 char 截断，中文字符为 2 char 可保证完整性。如需要按 codepoint 截断可后续优化 |
| "匿名用户" 硬编码 | 国际化困难 | 小需求阶段可接受，后续可提取为常量或配置 |
